# F-A11Y-002 — Dynamic type

Status: done | Priority: P1 | Phase: 6
Reads: 24-DESIGN-SYSTEM#accessibility-baseline

## Spec

Full functionality at 200% system text scale. This constrains how many columns
the set row can carry, which is why it's a design constraint from the start
rather than a later fix.

## Implementation

Nothing needed building: the constraint was honoured as the spec intended,
continuously rather than at the end — `SetRow` has switched to a stacked layout
above `textScaler.scale(16) > 22` since `F-LOG-003`, and every later screen was
built on the same components.

What this feature adds is the **proof**: `test/features/a11y/accessibility_test.dart`
pumps all eleven top-level destinations at `TextScaler.linear(2)`. A screen that
overflows throws during layout, so arriving at all is the assertion — and a new
screen added without thinking about scale now fails there rather than in
review. `pumpApp` gained `textScale` to make that possible; `pumpScreen`
already had it.
