# F-A11Y-001 — Screen reader support

Status: done | Priority: P1 | Phase: 6
Reads: 24-DESIGN-SYSTEM#accessibility-baseline

## Spec

Semantic labels on every interactive element. Set rows announce meaningfully —
"set 3, working, 100 kilograms, 8 reps, completed" — rather than reading out raw
cell contents. Charts carry a text summary alternative, since a line chart is
otherwise entirely inaccessible.

## Implementation

- Set rows already announced as whole sets (`SetRow._semanticLabel`, shipped
  with `F-LOG-005`) — the spec's own worked example was the first thing built,
  not the last.
- Charts are **replaced** for a screen reader, not annotated:
  `lib/core/a11y/chart_summary.dart` builds the sentence, the widget wraps the
  plot in `Semantics(label:) + ExcludeSemantics`. Without the exclusion
  fl_chart's axis labels read out as a stream of loose numbers underneath the
  summary, which is worse than silence.
- Every summary has the same shape — what it is, how much of it there is,
  where it starts and ends, its extremes. Someone listening to four charts on
  the Insights tab should not have to learn four formats.
- `TrendChart` and `WeeklyBarChart` both take a required `metricLabel`, so a
  new chart cannot be added without deciding what it announces.
- The three hand-drawn widgets get the same treatment: `CalendarHeatmap` says
  the count and the window, `BodyMapHeatOverlay` names its three hottest
  regions rather than reading out twenty, and `PlateStackVisualization` takes
  the sentence from its caller — only the caller knows the display unit.
- Icon-only buttons without a tooltip were the other gap; two remained
  (history's set-note button, plate settings' two "add" buttons, which
  announced only "Add" on a screen with two of them).
