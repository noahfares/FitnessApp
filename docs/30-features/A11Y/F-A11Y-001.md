# F-A11Y-001 — Screen reader support

Status: done | Priority: P1 | Phase: 6
Reads: 24-DESIGN-SYSTEM#accessibility-baseline

## Spec

Semantic labels on every interactive element. Set rows announce meaningfully —
"set 3, working, 100 kilograms, 8 reps, completed" — rather than reading out raw
cell contents. Charts carry a text summary alternative, since a line chart is
otherwise entirely inaccessible.

## Status note

Verified on a real device (Samsung Galaxy S24+, TalkBack enabled via `adb
shell settings put secure enabled_accessibility_services`) rather than by
render test alone. `adb shell input tap`/`swipe` bypass TalkBack's touch
exploration entirely (confirmed via `dumpsys accessibility`, which reported
no accessibility-focused window after a synthetic swipe), so gesture-driven
linear navigation couldn't be driven from the host — instead, the
accessibility node tree itself (`uiautomator dump`, the same
`AccessibilityNodeInfo` data TalkBack reads and speaks from) was audited
directly across the dashboard, the exercise picker, the active workout
screen's set row, the session summary, and the Insights chart. Every
interactive element carries a real label in a sensible top-to-bottom order;
the bottom nav announces "Tab 2 of 5" style position; a completed set reads
"Set 1, lb 111, Reps 5, completed, personal record"; the weekly-volume bar
chart's `Semantics` wrapper reads "Bar chart, 1 bars from Aug 9 to Aug 9.
Highest: Aug 9 555" — the text-summary alternative this spec names, present
and accurate. One real bug found and fixed this way, that no render test
could have caught (it doesn't throw or overflow, it just speaks wrong):
`RestTimerBar`'s `Semantics(label: ...)` wrapped a `LinearProgressIndicator`
without excluding it from semantics, so the indicator's own raw percentage
value merged into the parent label, producing a stray leading number before
the real sentence ("17, Rest timer, 2 minutes 28 seconds remaining" instead
of "Rest timer, 2 minutes 28 seconds remaining"). Fixed by wrapping the
indicator in `ExcludeSemantics`, the same pattern batch 6.1 already used for
chart canvases; confirmed fixed against a rebuilt debug APK on the same
device. Not verified: real TTS announcement timing/interruption behaviour
and gesture-based navigation order, both of which need either a real finger
or an Espresso/UI Automator test harness beyond what this session's plain
`adb shell input` tooling can drive.
