# F-A11Y-005 — Reduce motion

Status: done | Priority: P2 | Phase: 6
Reads: 24-DESIGN-SYSTEM#accessibility-baseline

Honour the system reduce-motion setting: no chart animations, no PR celebration
animation, instant transitions.

---

## Localisation — `I18N`

## Implementation

- `lib/core/a11y/motion.dart` is the single seam: `prefersReducedMotion`,
  `motionDuration`, and `ReduceMotionPageTransitionsBuilder`. Every animation
  routes through it rather than reading `MediaQuery.disableAnimations` itself,
  so honouring the setting is one decision made once instead of a rule each new
  widget has to remember.
- Applied to the three animations that exist: both charts' fl_chart transitions,
  the PR badge's entrance (`F-LOG-013`'s "brief, non-blocking animation" — the
  record still shows, only the flourish goes), and route transitions app-wide
  via `ThemeData.pageTransitionsTheme`.
- Route transitions are made *visually* instant; the route's own
  `AnimationController` still runs its course underneath, driving nothing. Zeroing
  it would mean a `CustomTransitionPage` on all thirty-odd routes, and the
  observable behaviour — nothing moves — is identical. The test asserts exactly
  that: the destination's position on arrival equals its position after
  settling, with a control test proving the same screen does move otherwise.
- Nothing removes a state change, only its transition. Reduce motion means
  arriving instantly, never arriving less.
