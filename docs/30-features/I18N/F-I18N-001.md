# F-I18N-001 — String externalisation

Status: done | Priority: P1 | Phase: 6
Reads: 22-UNITS, 24-DESIGN-SYSTEM

## Spec

All user-facing strings in ARB files from the start, even while English-only.
Retrofitting extraction across a finished app is miserable and never quite
complete; doing it continuously costs almost nothing.

`ImportScreen`, and `PlateSettingsScreen` — the three larger sub-screens

bug surfaced and fixed in passing, not just translated: the wipe
confirmation dialog asked the user to type "DELETE" but compared
`controller.text` against the hardcoded literal `'DELETE'` — once the
prompt became `l10n.dataWipeConfirmKeyword`, comparing against a
hardcoded English string would have silently broken the flow for any
future non-English locale (the displayed word and the required word would
diverge). The fix is structural, not just cosmetic: `dataWipeConfirmKeyword`
is now read once and used for *both* the display text and the
`controller.text == keyword` check, so the two can never disagree
regardless of locale. `ImportScreen` gained two ICU plurals
(`importUnresolvedMessage` for the unresolved-exercise-name count,
`importSkippedSuffix` for the already-imported-workout count) properly
pluralized via ICU rather than the source code's own ad hoc
`length == 1 ? '' : 's'` ternaries — a real improvement over the
`"(s)"`-style shorthand those ternaries produced, the same treatment
`plateSettingsPairsAvailable` gives `_PlateRow`'s own `"pair(s) available"`
text; unlike the routine-delete `ADR-0004` citation earlier passes found
and *preserved* verbatim, a crude but grammatically legible plural marker
isn't broken user-facing copy, so cleaning it up through ICU while
translating is squarely in scope. `importResultMessage`'s "workouts"/"sets"
wording is deliberately left non-pluralized (plain `{workouts}`/`{sets}`
placeholders, no ICU) because the source string never conditioned on count
either — preserving that one exactly, unlike the two it did fix, since a
translator changing grammar the original English never had would be
inventing behaviour, not correcting it.

A twelfth pass closed `AppShell`'s own long-standing deferral. Its five
destinations were a `static const List<ShellDestination> destinations` —
a compile-time constant, which can't call into `AppLocalizations` at all,
since resolving a string from it needs a `BuildContext` that doesn't exist
at const-evaluation time. The fix is the same shape as `weekdayAbbreviations
(l10n)` from the sixth pass: the constant became `static List<ShellDestination>
destinationsFor(AppLocalizations l10n)`, called once in `build()` with the
screen's own `l10n`. Four of the five labels reuse another screen's exact
app-bar title rather than mint a duplicate — `routinesTitle`, `startWorkoutTitle`,
`historyTitle`, `insightsTitle` — since a tab and the screen it opens onto
are naming the same thing. The fifth, "Home", has no matching key anywhere
else: the dashboard's own app bar shows the FitnessApp brand name instead
of the word "Home", so `shellHomeLabel` is a new key existing for this one
purpose. `navigation_test.dart`'s "shows five destinations" test — the
reason this was deferred in the first place — now resolves `AppLocalizations`
from a pumped widget's `BuildContext` (`AppLocalizations.of(tester.element
(find.byType(NavigationBar)))!`) and calls `destinationsFor` with it,
rather than reading the old static field directly; every other assertion
in the test was already generic over `destination.label` and needed no
change.

A fourteenth and final pass closed that unit, and with it the whole
feature. `fieldHeader()` (`set_value_format.dart`) gained an
`AppLocalizations` parameter — the same threading-not-widening approach
`weekdayAbbreviations`/`_kindLabel` used earlier — updated at all three of
its real call sites (`ActiveWorkoutScreen`'s `_ColumnHeaders`,
`NumericKeypadSheet`, `SetRow._semanticLabel`). `NumericKeypadSheet` turned
out to be unmigrated as a whole file, not just its `fieldHeader` call —
tooltips ("Start/Stop stopwatch", "Plate calculator"), stepper semantic
labels ("Decrease"/"Increase"), and the digit-key sheet's own semantics
("Decimal point", "Backspace", "Clear") all moved to ARB in the same pass,
since the file was already open for the one call site and leaving the rest
literal would have been an arbitrary half-migration. `SetRow`'s
`_semanticLabel` — the accessibility string a screen reader announces per
row (`F-A11Y-001`) — is the most structurally composed string in the app:
built from independently-translated fragments (`"Set {number}"`,
a field-header-plus-value pair per tracked field, an RPE/RIR clause, a
completion-status word, optional note/PR clauses) joined with `', '`. Each
fragment got its own key rather than one giant templated sentence, since
the set of fields and optional clauses varies per exercise and per
setting — the same reasoning ARB's own plural/placeholder system already
assumes: compose translated fragments, don't template full sentences.
`RestTimerBar`'s spoken-remaining-time label similarly composes
`restTimerBarMinutes`/`restTimerBarSeconds`, both real ICU plurals (unlike
the source's `minutes == 1 ? 'minute' : 'minutes'` ternary, the same
crude-ternary-to-ICU cleanup the eleventh pass already applied to
`ImportScreen` and `plateSettingsPairsAvailable`). Several keys reuse
exact matches from other already-migrated screens rather than duplicate
them: `historyEditDoneAction` (the keypad's own "Done" button),
`historySetRowCompleteSemanticLabel`/`historySetRowDeletedSnackbar`
(identical to `SetRow`'s own completion checkbox and delete-undo
snackbar — `HistorySetRow` and `SetRow` really do say the same two things),

none asserted against the composed semantic-label strings directly, and
every literal-text assertion (`find.text('Add set')`,
`find.byTooltip('Start stopwatch')`, etc.) matches
`AppLocalizations`'s English value exactly, the same as every other pass
in this file.
