# F-I18N-001 — String externalisation

Status: in-progress | Priority: P1 | Phase: 6
Reads: 22-UNITS, 24-DESIGN-SYSTEM

## Spec

All user-facing strings in ARB files from the start, even while English-only.
Retrofitting extraction across a finished app is miserable and never quite
complete; doing it continuously costs almost nothing.

## Status note

Batch 6.2 migrated `SettingsScreen` alone as the first proven slice. This
pass adds four more: `DashboardScreen` and `HistoryScreen` (two of the five
tab-root screens), `RoutineListScreen` (a third, plus the shared
`promptRoutineName` rename/create dialog it defines and every other routines
screen calls), and `ConfirmSheet` — the one confirmation sheet every
destructive action in the app goes through, so its default `confirmLabel`/
`cancelLabel` moved from a literal parameter default (Dart requires those to
be compile-time constants, which a `BuildContext`-resolved string can't be)
to a null default resolved from `AppLocalizations` in the function body.
ICU plurals (`{count, plural, one{...} other{...}}`) cover exercise counts
on both the dashboard's and history's workout tiles — two separate ARB keys
with identical English text, matching this file's own existing
per-screen-prefix convention rather than introducing a shared, unprefixed
key. Deliberately not touched: `AppShell`'s bottom-navigation labels are a
`static const List<ShellDestination>` — a compile-time constant an existing
test (`navigation_test.dart`) asserts against directly — and turning it
into something `AppLocalizations`-aware needs a real restructure (an
instance getter or a `BuildContext` parameter), not a mechanical
find-and-replace, so it's left for a batch that can give it its own
attention rather than folded in here as a side effect. Found and preserved,
not silently fixed: the routine-delete confirmation message contains a
literal internal doc citation, `` (`ADR-0004`) ``, that reads as broken copy
to a real user — moved into ARB verbatim rather than quietly rewritten
mid-migration, with a follow-up task filed to fix the copy itself
separately. Every other screen — catalogue, insights, the rest of routines,
the rest of logging and history, body, all of analytics beyond what's
covered — is still English-string literals, left for future batches.

A further pass added the last two tab-root screens: `ExerciseCatalogScreen`
(including the archive-by-equipment flow's plural+placeholder combo,
`{count, plural, =0{Nothing to archive.} one{...} other{...}}` — the ICU
zero-selector handling both the empty-result and normal-count cases in one
key rather than a separate literal check) and `InsightsScreen`, by far the
largest single-screen migration yet (over 40 keys: every section heading,
empty/insufficient-data state, explanatory paragraph, and the
`RangePreset`/rep-range-bucket-adjacent prose). Deliberately left as
literals within `InsightsScreen`, on the same reasoning `docs/22-UNITS.md`
already applies to unit symbols: the rep-range (`1–3`, `21+`) and
intensity-zone (`<60%`, `90%+`) bucket labels, and every chart
`valueLabel`/axis formatter closure (`'${v} min'`, tabular percentages) —
these read as formatted numeric ranges, not translatable prose, the same
category this file already excludes `QuantityFormatter` output from.
`date_range_selector.dart`'s own chip labels are a separate widget file
this pass didn't touch, so the range-preset prose now exists in ARB twice
under different names for the two different places it's read from
(`InsightsScreen`'s own `_rangeLabel` vs. the selector's chips) — a
duplication to reconcile if that selector is migrated later, not a bug now.

All five tab-root screens (Dashboard, Routines, Start, History, Insights)
are now migrated at their top level; `ExerciseCatalogScreen`, reached from
Dashboard, makes it six real screens deep. Still English literals: every
routine/exercise sub-screen beyond the list (editor, day editor), the rest
of logging (active workout, start, summary), the rest of history (detail,
edit), body, `ConsistencyScreen`/`PrTimelineScreen`, every Settings
sub-screen beyond the root, `AppShell`'s nav labels, and onboarding.
